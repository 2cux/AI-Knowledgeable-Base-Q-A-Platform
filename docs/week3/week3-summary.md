# 第三周项目收尾总结

## 1. 第三周目标

第三周的目标不是继续扩张功能数量，而是把前两周已经完成的知识库、文档、Embedding、RAG 问答链路补成一个可展示、可验收、可面试讲清楚的闭环。

本周重点包括：

- 补齐 RAG 质量闭环：检索命中语义、拒答策略、答案抽取、引用追溯、最小评估样例。
- 补齐会话系统闭环：conversation / message 模型、多轮上下文、会话列表和详情。
- 补齐文档生命周期闭环：状态字段、重处理、重新向量化、删除关联数据、可重试能力。
- 补齐管理端基础运营能力：问答详情、未命中问题、反馈、热门问题、基础统计。
- 开始从 MVP 开发阶段转向投简历前的项目包装阶段。

## 2. 第三周实际完成内容

结合当前代码，第三周已经落地的能力包括：

- `chat_record` 增加 `answer_status`、`raw_retrieved_chunk_count`、`conversation_id`、`citations_json` 等追溯字段。
- `AnswerStatus` 已包含 `SUCCESS`、`NO_HIT`、`WEAK_HIT`、`LLM_UNAVAILABLE`、`RETRIEVAL_UNAVAILABLE`。
- `RetrievalSearchVO` 已区分 `rawChunks`、`effectiveChunks`、`rawRetrievedChunkCount`、`effectiveChunkCount`、`minEffectiveScore`。
- `AnswerExtractor` 已负责从 LLM 原始响应中抽取最终答案，兼容多种响应结构。
- `conversation`、`message` 表和实体已存在，`chat/ask` 会写入 `chat_record`、`conversation`、`message`。
- 用户端已提供会话列表、会话详情、问答记录列表、问答详情、反馈提交接口。
- 文档已支持 `process`、`embed`、`force=true` 重处理 / 重新向量化、状态查询、任务查询、删除闭环。
- 管理端已提供问答记录、问答详情、未命中问题、反馈列表、热门问题 TopN、基础统计接口。
- 已存在 RAG 最小评估资料：`docs/rag-eval/rag-eval-cases.md`、`rag-eval-cases.json`、`rag-eval-knowledge.md`。

## 3. 第三周完成的核心模块

- RAG 问答模块：检索、拒答、LLM 生成、答案抽取、引用溯源、问答记录落库。
- 会话系统模块：会话创建 / 复用、消息双写、多轮上下文加载。
- 文档生命周期模块：上传、处理、切片、Embedding、状态聚合、重试、删除。
- 管理端运营模块：未命中治理、反馈运营、热门问题、基础统计。
- 工程化安全模块：JWT、Spring Security、管理员权限校验、AI Debug 开关、API Key 环境变量配置。

## 4. 当前系统阶段判断

当前系统已经从“能跑通单次问答的 MVP”进入“投简历前收尾包装阶段”。

后续不建议继续大规模加功能，例如复杂知识库协作、权限体系扩展、后台页面、生产级向量库接入、异步任务队列等。这些方向可以作为面试中的后续优化点，而不应该继续压缩面试准备时间。

更合理的重点是：

- 修复 README、docs、SQL、注释中的乱码。
- 验证 Flyway 空库初始化。
- 用 Apifox 跑通核心链路。
- 准备示例数据、简历描述和面试讲解稿。

## 5. 当前项目是否具备简历展示价值

具备。

原因是项目已经不只是 CRUD，而是包含了 Java 后端实习面试中较有价值的完整链路：

- 用户认证和 JWT 权限控制。
- 知识库、文档、任务、问答、反馈、运营统计等多模块数据建模。
- 文档切片、Embedding、RAG 检索、LLM 生成、引用溯源。
- 会话系统和多轮上下文。
- 文档重处理、重新向量化、删除一致性。
- Flyway 数据库版本管理和 Apifox 验收思路。

但简历中需要如实表达：当前是 MVP 级 RAG，向量存储在 MySQL，检索由 Java 侧计算相似度，不应描述为生产级向量数据库或高并发分布式系统。

## 6. 第三周最大的技术收获

第三周最大的收获是从“做出功能”转向“做出可解释、可追溯、可运营、可恢复的系统”。

具体体现在：

- RAG 不只返回答案，还要知道命中了什么、为什么拒答、引用来自哪里。
- 文档处理不只写入 chunk，还要考虑重处理、失败状态、旧数据清理和删除一致性。
- 多轮对话不适合只依赖 `chat_record`，需要用 `conversation` 和 `message` 表承载上下文。
- 管理端统计虽然基础，但能让知识库迭代有数据依据。

## 7. 第三周遗留问题

- README 当前存在乱码，启动说明不完整，需要重写或修复。
- 部分 Controller 注释、Swagger 描述、SQL 注释存在乱码，投简历前应集中处理。
- Flyway 空库初始化尚需实际验证。
- Apifox 核心链路验收文档需要补齐并执行。
- 示例数据和演示问题需要准备。
- 当前 RAG 是 MySQL + Java cosine 检索，适合 MVP，不适合夸大为生产方案。
- 当前没有看到 Redis、RabbitMQ、微服务、高并发压测等实现，简历中不应写。

## 8. 第四周或投简历前重点

第四周应停止大规模功能开发，进入“功能收尾 + 项目包装 + 面试准备”：

- 第 1 优先级：项目可运行、空库可初始化、核心链路可验收。
- 第 2 优先级：README、API 文档、验收说明、示例数据。
- 第 3 优先级：简历项目描述、30 秒 / 2 分钟 / 5 分钟讲解稿。
- 第 4 优先级：准备高频追问和不足说明。

做到这些后，就可以停止继续开发，把后面一周留给 Java 基础、Spring、MySQL、项目讲解和模拟面试。
