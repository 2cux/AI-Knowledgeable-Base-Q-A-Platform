# 投简历前项目打磨计划

目标：在本月中旬前完成项目可展示性收尾，把后续一周留给面试准备。

## A. 必须完成，否则不建议投简历

| 任务 | 为什么重要 | 预计耗时 | 验收标准 | 是否阻塞投简历 |
|---|---|---:|---|---|
| README 完整重写或补齐 | 当前 README 存在乱码，面试官打开会直接扣分 | 0.5 天 | README 包含项目介绍、技术栈、启动步骤、环境变量、核心接口链路 | 是 |
| 检查 README / docs / SQL / 注释乱码 | 当前 Controller 注释、README、部分 SQL 注释有乱码 | 0.5 天 | 主要展示文档无乱码，核心注释可读 | 是 |
| Flyway 空库初始化验证 | 投简历项目必须能从空库启动 | 0.5 天 | 新建空库后应用启动成功，V1-V18 迁移通过 | 是 |
| 环境变量配置说明 | LLM / Embedding 依赖 API Key，必须说明如何配置 | 0.25 天 | README 明确 `APP_LLM_API_KEY`、`APP_EMBEDDING_API_KEY`、base URL、model | 是 |
| API Key 泄露检查 | 密钥泄露是严重安全问题 | 0.25 天 | `rg` 检查无真实 key，日志不打印完整 Authorization | 是 |
| 核心链路 Apifox 验收 | 证明项目不是只写了代码，而是能跑通 | 1 天 | 注册、登录、建库、上传、process、embed、ask、详情、反馈、管理端统计跑通 | 是 |
| 示例数据准备 | 面试演示需要稳定数据 | 0.5 天 | 准备 1 个知识库、1-2 个 txt / md 文档、3 个命中问题、2 个未命中问题 | 是 |
| 简历项目描述 | 需要能直接投递 | 0.25 天 | 形成 4-6 条真实 bullet points | 是 |
| 面试讲解稿 | 项目复杂度较高，需要提前组织语言 | 0.5 天 | 准备 30 秒、2 分钟、5 分钟版本 | 是 |
| 常见问题准备 | 面试官会追问 RAG、权限、数据库、缺点 | 0.5 天 | 至少准备 20 个高频问答 | 是 |
