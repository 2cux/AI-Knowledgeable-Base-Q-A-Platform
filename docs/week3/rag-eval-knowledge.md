# RAG 回归测试固定知识源

本文档用于上传到“RAG 回归测试知识库”，作为第三周最小 RAG 评估集的固定知识源。它只服务于回归测试，不代表完整产品说明。

## 文档生命周期

文档上传成功不代表已经完成解析，也不代表用户可以立即基于该文档问答。上传成功只说明原始文件已经被系统接收。只有当文档完成解析、切片和 embedding 后，相关内容才具备被检索和回答引用的条件。

解析负责从原始文档中提取文本内容。切片负责把较长文本拆成适合检索和提供给模型的 chunk。embedding 负责把每个 chunk 转换成向量，用于后续相似度检索。三者是连续关系：先解析，再切片，再生成 embedding。

## 命中语义

`matched` 表示系统是否找到了足够可信、可以支撑回答的有效检索证据。它不应该只表示 LLM 是否返回了文本，也不应该只表示数据库里是否存在原始召回结果。对于没有有效证据的问题，`matched` 应该为 false。

`rawRetrievedChunkCount` 表示向量检索阶段原始召回的 chunk 数量。`retrievedChunkCount` 表示经过有效性筛选后，真正进入回答上下文和引用追溯的 chunk 数量。两者可能相同，也可能不同。弱相关内容可能出现在 raw 召回中，但不应该进入有效引用。

## 引用追溯

`citations` 用于说明答案依据了哪些文档片段。一个 citation 至少应该能帮助定位到文档和 chunk，例如 `documentId`、`chunkId`、`chunkIndex`、`documentName`、`score` 和 `contentSnippet`。用户端和管理端的问答详情都应该保留这些追溯字段，方便排查命中质量和回答来源。

## AnswerExtractor

`AnswerExtractor` 的职责是从真实 LLM 返回结构中抽取最终可展示答案。用户端、管理端和数据库中保存的答案都应该是稳定文本，而不是上游模型的原始 JSON、choices、message 或其他内部结构。对于空回答、异常结构和无效结构，AnswerExtractor 应该提供兜底处理，避免把不可读内容直接展示给用户。

## 拒答与降级策略

`NO_HIT` 表示没有找到任何可用检索证据，系统应该明确说明知识库中未找到相关内容，不能编造答案。

`WEAK_HIT` 表示存在少量相似内容或低质量召回，但证据不足以支撑可信回答。系统应该保守拒答，提示当前知识库证据不足，而不是把弱相关内容包装成确定结论。

`LLM_UNAVAILABLE` 表示检索可能已经命中，但模型服务不可用或调用失败。此时系统可以保留 citations 和检索追溯信息，但回答文本应明确说明模型暂时不可用，建议稍后重试，不能伪装成正常生成成功。
